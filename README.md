# 净滩记述中

柳涧两岸的志愿巡查台账全为合成资料。每个季节允许有几场实际巡查。质重单位是千克，件数只能在同类型之间比较。

## 资料格式

数据位于 `data/records.json`，以 UTF-8 保存。各表的记录以本表内的 `id` 或 `seq` 识别。原话保留提交时的文字。

现场常把相邻两段叫作一段，以河岸示意登记的方向与边界为标准。segments 的 from_m 到 to_m 是本岸朝下游的米数，左闭右开。visit effort_minutes 只是组织时长，有记录才能分给各段。规则记录本轮有效比较至少需要的重叠范围和努力条件。正文中的数字是作者的观察或转述，不是既定统计。

- `segments` 保存示意图的实体登记。 字段为 `id`、`bank`、`from_m`、`to_m`、`aliases`。
- `visits` 保存履行巡查时的基本登记。 字段为 `id`、`season`、`at`、`team`、`bank`、`effort_minutes`、`weather`。
- `notes` 保存来自参与者的巡查叙述。 字段为 `id`、`visit`、`writer`、`text`。
- `rounds` 保存季节比较的公开口径及补测时限。 字段为 `id`、`seasons`、`metric`、`allowed_weather`、`effort`、`min_overlap`。
- `bulletins` 保存已给社区的旧报告栏目，part 指主表中相关一级栏目。 字段为 `id`、`part`、`articles`、`citations`、`text`。

## 查看资料与自检

使用 Python 3.11.2 自带的标准库读取资料并验证字段和引用。

```sh
python3 -m json.tool data/records.json
python3 -m unittest discover -s tests -v
```

## 生成有范围说明的公开报告

`beachwatch` 包只读 `data/records.json`，不修改原始资料。它按原话抽取岸别、
地标、相对方向、起止范围、量词和否定（没见到、没走到、没过秤），再按公开
口径判断哪些范围可以比较。

```sh
python3 -m beachwatch                        # 最新季节，分岸展示，居民可读文本
python3 -m beachwatch --season 暖季B --format json
python3 -m beachwatch --mode whole_bank      # 全岸展示（精确度随口径下降）
```

报告包含九部分：

1. **范围说明**——走过哪些米、哪里没走到、哪里称过重、哪些是"没见到"
   而不是零；
2. **当前可比范围与公开解释**——只在两期共有且观测努力可比的范围成立，
   附手记编号；
3. **未决差异（分析员用）**——几种合理归属会改变改善与否时，列出每种
   可能，不替分析员选；
4. **袋数与批次**——同一袋被两人记到时只算一袋；
5. **旧栏目复核与更正**——每条旧结论是"仍成立"还是"失去依据"，并给出
   对应 `part` 的更正稿；
6. **补交清单后的复核**——先前哪条结论仍成立、哪条失去依据，以及哪些
   小计/总计要一并替换；
7. **汇总栏检查**——两栏区间依赖同一批无法分开的数量时，不把上下限相加；
8. **发布人员按原栏目领取更正**——每个 `part` 的原文、更正稿、连带替换的
   小计/总计，以及仍可引用的独立记录；
9. **按实际口径展示**——分岸或全岸切换时，居民看到的精确度与比较范围
   服从实际统计口径。

下一季录入合格资料后，重跑同一命令即可得到新的当前可比范围与公开解释；
旧季的原话、岸段与引用仍可按手记编号查回。

### 几条硬规则

- 没走完的范围只计实际能核定的部分，名义终点单独保留（N2 名义到 220 米、
  实走 170 米；N4 只在 120–190 米，名义到 260 米）；
- "两段共 10 个"是组总量，不按平均摊到各段，也不按段重复累计；
- 两人记载的同一袋只算一袋，同一批只算一次重量；
- 没有观察也没有计量依据的空白是"无资料"，不是零；确认未见才是零；
- 天气或作业时长不达公开口径时，观察保留，但不进入比较；
- 两场合称不能拆到单岸，汇总栏不把共享批次的上限/下限直接相加。

### 当前资料下最容易被误读的几处

- N2 的"6 公斤"是左岸自己两段与渡台队各自带来的袋合称，称点在桥下，
  不能当作左岸或右岸的单独重量；N7 只是补写批号，不新增重量；
- N1 的 12 个瓶是"前两段"（L1、L2）的合计，不能反推某一段；同手记的
  5 个属于 L3，两者互补，不重复；
- N3 的 10 个是"那两段"（L1、L2）的合计，原话明确"没有按段数"；它
  与上期 12 个长度不同，不能相除；
- N8 的"桥边水里"瓶没走近、不能确定在哪段，可能落在 R1–R3；因此
  "右岸渡台瓶件少于上期"仍为方向未定，而不是已经改善；
- N4 的"没见瓶"只在确实走完的 R1 成立；R2 只走到一半且没过秤，不能
  把没走到的部分记成零。

### 资料局限

原话解析是规则式的，只覆盖台账里实际出现的说法（渡口、桥上弯、桥下、
柳栏、石渠、对岸渡台、桥对岸、南灯桩，以及"往下/走到 N 米/一半/封着/
避水/没过秤/同一批/批号"等）。遇到新说法时，解析器会把它留在
`no_data` 或未决栏，而不是猜一个数；补充新说法时应同时补测试。
